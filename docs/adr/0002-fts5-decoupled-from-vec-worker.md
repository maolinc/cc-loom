# FTS5 解耦到入队时写，"ready" 只指向量索引

能力市场的索引分两层：词法（FTS5，本地即时）与语义（vec，依赖限频外部 embedding API）。二者**解耦**：FTS5 在能力保存/导入的入队时刻**同步写入**（本地 SQL insert，且文本构造本就是算 content_hash 要做的事）；vec 的生成留作后台 worker 异步。

理由：若把 FTS5 与 vec 耦合在 worker 里一起写，则新能力在 vec 生成完成前（受 API 限频可能数分钟）**连词法搜索都不可见**——大批量导入时市场会短暂出现"零结果"。解耦后词法召回始终是最新的，vec 是尽力而为的语义增强。

由此确立不变量：**每条非软删、非 adopted 的能力永远有 FTS5 行**。`asset_embeddings.status='ready'` 只表示 vec 侧完成；未 ready 的能力仍可经 FTS5 被词法召回，在融合时其语义分记 0。该不变量也是"模型变更重建期间搜索降级为纯词法而非无搜索"的兜底（见设计文档 §4.3 / §5.6）。
